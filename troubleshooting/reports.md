# 📄 Reports & SBOM Troubleshooting — SMP V9.4.2

## PDF not generated: ReportLab not installed

```bash
source venv/bin/activate
pip install reportlab

# Verify
python3 -c "import reportlab; print(reportlab.Version)"
```

HTML report is always generated regardless. If ReportLab is unavailable, you'll see:
```
ReportLab not installed — PDF report skipped.
```

---

## PDF is empty / 0 bytes

ReportLab encountered an error mid-generation. Check logs:
```bash
tail -50 logs/scan.log | grep -i "pdf\|report\|error"
```

Common cause: Unicode characters in finding titles. SMP uses `_esc()` on all text — if a finding title from a scanner includes raw bytes, file a bug with the finding source.

---

## SBOM generation failed

```
SBOM generation failed (non-fatal): No module named 'cyclonedx'
```

```bash
pip install cyclonedx-python-lib
```

Fallback chain — SMP tries in order:
1. CycloneDX JSON (preferred)
2. SPDX tag-value
3. CSV (always works)

So even without the package, a CSV SBOM is always generated.

---

## SBOM is empty (no components)

The SBOM is built from technology fingerprinting data. If no technologies were detected during the scan (WhatWeb, HTTPx, Tech Fingerprint all returned nothing), the SBOM will have zero components.

**Fix:** Ensure the target responded to HTTP probes. Check the narrative log for WhatWeb output.

---

## Report verification: hash mismatch

```
✘  TAMPERED — content hash does not match embedded hash
```

**Causes:**
- PDF was modified after SMP generated it (re-saved, metadata edited, page added)
- PDF viewer "saved" the file, changing it
- File corrupted during transfer

**Fix:** Re-generate from the scan:
```python
from tools.db_manager import get_findings_for_scan, get_targets
from tools.report_generator import generate_scan_reports

findings = get_findings_for_scan(scan_id)
target   = get_targets()[0]   # or specific target dict
generate_scan_reports(scan_id, target, findings)
```

## Report verification: hash not found in file

```
✘  ERROR — no SMP content hash found in this file
```

This is not an SMP-generated report, or it was generated by SMP V6 or earlier (pre-hash embedding). V9.4.2 embeds hashes in all new reports.

---

## HTML report missing styles (looks unstyled)

The HTML report is self-contained (inline CSS). If it looks unstyled, the file may have been truncated. Check file size:
```bash
wc -c reports/html/SMP_*.html
# Should be > 50 KB for a typical scan
```

Re-generate if too small.

---

## Reports directory not created

```bash
mkdir -p reports/html reports/pdf reports/sbom
```

SMP calls `init_directories()` on startup which creates these automatically. If missing, the startup may have failed before this point (check for SQLCipher error).

---

## PDF missing findings (truncated)

Each finding gets its own page in Section 5. Very large scans (500+ findings) generate large PDFs. If findings appear cut off, the disk may have been full during generation.

```bash
df -h reports/
```
